LocalTranslateAccess : traduction locale pour NVDA

LocalTranslateAccess traduit les textes annoncés par NVDA, pour une application ou pour toutes les applications. Les traductions sont calculées sur votre ordinateur. Cette édition est une première version expérimentale avec choix et téléchargement des modèles.

Raccourci et menu de traduction

L’extension n’a qu’un seul raccourci : NVDA + Ctrl + Maj + T. Il ouvre le menu de traduction, que vous parcourez avec les flèches. Validez avec Entrée ou appuyez sur la lettre indiquée.

  • Traduction pour cette application (A) : activer ou désactiver la traduction de tout ce que NVDA annonce dans l’application en cours. L’entrée est cochée lorsque la traduction est active.
  • Traduction globale (G) : activer ou désactiver la traduction dans toutes les applications. L’entrée est cochée lorsque la traduction est active.
  • Traduire la sélection (S) : traduire le texte sélectionné.
  • Traduire le presse-papiers (P) : traduire le texte copié.
  • Traduire la dernière annonce (D) : traduire ce que NVDA vient de dire.
  • Copier la dernière traduction (C) : placer la dernière traduction dans le presse-papiers.
  • Inverser les langues (I) : traduire dans l’autre sens.
  • Annoncer les langues (L) : entendre la langue source et la langue cible actuelles.
  • Configuration de la traduction (F) : ouvrir les réglages des langues et des modèles.

Une traduction courte est annoncée. Une traduction longue ou sur plusieurs lignes s’ouvre dans une fenêtre. Si le texte est déjà dans la langue cible, il est traduit dans l’autre sens.

Le raccourci peut être modifié dans le dialogue « Gestes de commandes » de NVDA, rubrique « LocalTranslateAccess ».

Configurer les langues sources et cibles

Ouvrez le menu NVDA, Préférences, LocalTranslateAccess. Le premier onglet « Langues » contient, dans cet ordre : « Langue source pour la traduction globale », « Langue cible pour la traduction globale », « Modèle pour la traduction globale », la liste des applications déjà configurées, « Langue source pour cette application », « Langue cible pour cette application », puis « Modèle pour cette application ». Les langues actuelles sont présélectionnées. Les applications sont affichées avec le nom stable de leur exécutable, sans le titre de la fenêtre ; changer de fenêtre ou de titre conserve les mêmes réglages et le même cache. Sélectionnez une application, puis appuyez sur Tab pour atteindre sa langue source. Choisissez Détection automatique ou une langue précise pour la source, puis une langue précise pour la cible.

Après la source et la cible, choisissez le modèle dans la liste correspondante, puis « Appliquer ». Seuls les modèles déjà installés compatibles avec les langues choisies sont proposés, y compris les paires intermédiaires lorsqu’elles sont installées. Le modèle actuellement utilisé est présélectionné s’il est compatible. Les modèles globaux et par application peuvent être différents. Vos choix sont conservés lorsque vous passez d’une application à l’autre, puis enregistrés avec « Appliquer ».

En source Automatique, un modèle doit couvrir toutes les langues sources prévues lors de la préparation de cette configuration, vers la cible choisie. La liste indique ces langues après « Auto ». Un modèle bilingue peut donc être proposé pour une seule source prévue ; un modèle multilingue peut en couvrir plusieurs. Auto concerne la détection de la langue, le modèle choisi reste fixe. Une langue détectée en dehors de la couverture installée ne peut pas être traduite ; le texte original est conservé. Si aucun modèle compatible n’est installé, un bouton « Télécharger un modèle pour la traduction globale » ou « Télécharger un modèle pour cette application » remplace la liste. Il ouvre directement les modèles compatibles avec les langues choisies et votre ordinateur. Les paires intermédiaires nécessaires sont préparées automatiquement. En mode Auto, toutes les sources prévues vers la cible sont prises en compte. Choisissez un modèle. S’il est déjà prêt, le bouton indique « Appliquer ». Sinon, choisissez « Télécharger » ; le bouton indique la progression, puis « Appliquer ». Après avoir choisi « Appliquer » dans cette fenêtre de téléchargement, vous revenez au premier onglet, avec le modèle installé sélectionné et le focus sur sa liste. Les autres choix en cours sont conservés. Le téléchargement n’enregistre pas les réglages : choisissez ensuite « Appliquer ». Annuler retourne au premier onglet sans changer les réglages.

La première langue cible par défaut est celle de la voix active du synthétiseur NVDA, lorsqu’elle est connue et prise en charge par le catalogue. Sinon, la langue de l’interface NVDA est utilisée ; en dernier recours, une langue disponible est choisie. Le choix est enregistré : changer de voix ensuite ne remplace pas une cible déjà configurée. Les cibles existantes sont conservées lors d’une mise à jour. Les langues régionales sont regroupées, par exemple fr-FR en français.

Vous pouvez modifier plusieurs applications avant de choisir « Appliquer » : les choix en cours sont conservés en passant d’une application à l’autre. Le bouton « Appliquer », placé après les réglages et visible sur la page Langues, enregistre les modifications pour les prochains démarrages de NVDA. La configuration de première activation est également conservée. Si aucune application n’est configurée, les listes de langues et de modèle correspondantes sont désactivées ; la source globale reste modifiable. Le deuxième onglet contient les modèles installés, le troisième le cache de traduction et le quatrième les performances. Le choix et le téléchargement des modèles se font dans l’assistant lors de l’activation de la traduction si des modèles manquent. Si un changement de langue exige des modèles manquants, un message indique de les préparer avec l’assistant.

Les annonces d’activation et de désactivation par application utilisent le titre de la fenêtre. Les réglages et le cache restent associés à l’exécutable.

Première utilisation

Le titre de l’assistant indique « Première utilisation pour cette application » avec le raccourci par application, et « Première utilisation » avec le raccourci global.

Aucun modèle de traduction n’est inclus dans l’installation. À la première activation par application ou en mode global, l’assistant s’ouvre directement sur les langues à traduire. Il n’y a pas de fenêtre préalable de confirmation de langue source. La langue du document ou une langue déjà détectée pour cette application est présélectionnée lorsqu’elle est disponible. Sinon, la détection du texte sous le focus se fait en arrière-plan et présélectionne le résultat si vous n’avez pas encore modifié la liste ni ajouté une paire. Une langue configurée manuellement est conservée. Vous pouvez modifier la sélection vous-même. Si aucune langue n’est déterminée, choisissez la source dans la liste. Les choix validés dans l’assistant sont enregistrés ; Annuler n’active pas la traduction. Les caractéristiques de votre ordinateur sont analysées en arrière-plan et ne sont pas affichées.

Tout se fait dans la même fenêtre : langues, paires, modèles et téléchargement.

  1. Sélectionnez une ou plusieurs langues sources avec les flèches et Espace. Choisissez la langue cible, puis « Ajouter ». La liste des paires et le bouton « Retirer la paire sélectionnée » apparaissent après le premier ajout. Vous pouvez ajouter plusieurs paires ; une source identique à la cible n’est pas ajoutée.
  2. La liste des modèles compatibles apparaît automatiquement sous les langues, sans bouton Valider ni changement de page. Elle se met à jour après chaque ajout ou retrait de paire. Seuls les modèles compatibles avec toutes les paires demandées et la machine sont proposés. Aucun modèle n’est recommandé. Les modèles sont classés par taille totale nécessaire, du plus petit au plus volumineux ; les tailles inconnues sont placées à la fin. Le premier modèle est sélectionné à l’ouverture. Les mises à jour des tailles gardent la sélection sur le premier élément tant que vous n’avez pas fait un choix ; ensuite votre modèle choisi est conservé. La taille totale inclut les paires intermédiaires, sans doublon ; un modèle multilingue est compté une seule fois. Les modèles déjà prêts portent la mention « installé ».
  3. Si le modèle choisi et ses ressources sont déjà installés, le bouton indique « Appliquer ». Cliquez pour enregistrer les langues et le modèle, fermer l’assistant et activer la traduction.
  4. Sinon, le bouton indique « Télécharger ». Pendant le téléchargement, vous restez dans la même fenêtre et le focus reste sur ce bouton, qui affiche un seul pourcentage global, calculé à partir du total des octets des moteurs et modèles nécessaires, y compris les paires intermédiaires. Un nouvel appui pendant l’opération ne relance pas le téléchargement. Aucune zone d’édition de téléchargement n’est affichée. Le bouton conserve la progression pendant la vérification et l’installation, puis devient « Appliquer ». Le pourcentage ne repart pas à zéro entre les fichiers. Les tailles sont recherchées avant le téléchargement ; si une taille reste inconnue, le bouton indique « Téléchargement en cours » jusqu’à ce que le total puisse être calculé. Seul le pourcentage global est annoncé pendant l’opération ; les noms des modèles et les étapes de décompression, conversion et installation ne sont pas annoncés. Les erreurs restent signalées. À la fin, le bouton devient « Appliquer ». Les listes de langues, de paires et de modèles restent visibles et accessibles avec Tab dans cette même fenêtre. Leurs valeurs sont conservées pendant l’opération ; vous pourrez les modifier après le téléchargement.
  5. Une fois l’installation terminée, le bouton devient « Appliquer ». Les langues et le modèle ne sont pas enregistrés avant ce clic. Choisissez « Appliquer » pour valider : l’assistant se ferme, puis le bip et l’annonce confirment l’activation pour l’application ou en mode global. La première paire définit la cible initiale des annonces. Annuler ferme sans enregistrer les choix ; les ressources déjà téléchargées restent disponibles.

Les langues et les modèles restent dans la même fenêtre : vous pouvez modifier les paires avant d’appliquer. Retirer la dernière paire masque la liste des modèles et les commandes inutiles. L’analyse de la machine et la recherche des tailles se font en arrière-plan. Les textes traduits ne sont pas envoyés à un service de traduction en ligne ; après l’installation des ressources nécessaires, la traduction fonctionne hors ligne.

La configuration se trouve dans le menu NVDA, Préférences, LocalTranslateAccess. Elle permet de modifier les langues et le modèle par application ou globalement. Si aucun modèle installé ne convient, le bouton de téléchargement remplace la liste des modèles. Après « Appliquer » dans cette fenêtre, vous revenez sur la liste du premier onglet ; son bouton « Appliquer » enregistre les réglages en cours.

Modèles disponibles

  • Argos Translate : modèles par paire de langues, calcul sur le processeur avec CTranslate2 en INT8.
  • Firefox / Bergamot : modèles par paire, calcul sur le processeur avec le moteur WebAssembly. Le moteur Node.js est téléchargé au premier choix de cette famille.
  • Marian / OPUS-MT : première paire proposée, anglais → français. Les poids originaux sont téléchargés puis convertis localement pour CTranslate2 en INT8. Le téléchargement est plus volumineux que le modèle installé.
  • SMaLL-100 330M INT8 : environ 344 Mo, un seul modèle pour 100 langues, avec CTranslate2 sur le processeur.
  • M2M-100 418M INT8 : environ 496 Mo, un seul modèle pour 100 langues, avec CTranslate2 sur le processeur.
  • NLLB-200 Distilled 600M INT8 : même modèle de base et précision INT8 que l’ancienne édition native5, avec une conversion CTranslate2 distribuée publiquement. Un téléchargement multilingue d’environ 643 Mo suffit pour toutes les paires couvertes dans la liste de l’addon, dont japonais → français et chinois simplifié → français. Le calcul est effectué sur le processeur ; l’assistant demande SSE4.1 et au moins 3 Go de RAM disponibles. Ce modèle est plus lourd que les petites paires Argos ou Firefox et peut être lent sur les anciens processeurs.
  • Hy-MT2-7B Q8_0 : modèle multilingue d’environ 8 Go, avec llama.cpp. Il utilise le CPU et la RAM par défaut ; le mode CPU demande au moins 12 Go de RAM disponibles. Une carte NVIDIA compatible avec au moins 11 Go de VRAM libre permet d’activer le mode GPU. Le choix est facultatif et les mêmes poids sont utilisés.

Utiliser la carte graphique

Après la liste des modèles, la case « Utiliser la carte graphique pour accélérer la traduction » apparaît uniquement lorsqu’une carte NVIDIA dédiée compatible dispose de suffisamment de VRAM libre pour le modèle et sa mémoire de travail. Elle est décochée par défaut : CPU et RAM. Cochez-la pour utiliser le GPU et la VRAM. Le choix est enregistré séparément pour chaque application et pour la traduction globale, dans l’assistant ou dans l’onglet Langues. Argos, Marian, NLLB, SMaLL-100, M2M-100 et Hy-MT2 peuvent utiliser ce mode ; Firefox/Bergamot reste sur CPU. Les modèles ne sont pas téléchargés à nouveau lors d’un changement de mode ; les bibliothèques GPU nécessaires sont téléchargées au besoin, avec une seule progression dans la même fenêtre. Si le GPU est indisponible au lancement ou manque de mémoire, l’addon utilise le CPU lorsque la RAM le permet et l’annonce. Les mesures CPU et GPU sont séparées dans Performances. Le gain dépend du modèle et du texte : les phrases très courtes peuvent rester plus rapides sur CPU.

SMaLL-100 et M2M-100 privilégient la rapidité avec une seule hypothèse de traduction (beam size 1), au prix possible de traductions moins précises. Ils demandent SSE4.1 et au moins 2 Go de RAM disponibles selon la règle prudente de cette édition. Un seul téléchargement sert toutes leurs langues. La détection automatique reste séparée et conserve son propre coût ; choisir la source manuellement évite cette étape. Comparez les temps de traduction réels sur votre machine dans les performances.

Les GPU AMD et Intel sont détectés, mais leur accélération n’est pas encore proposée dans cette édition. Les ressources partagées d’une carte intégrée ne sont pas comptées comme de la VRAM dédiée. Seuls les modèles compatibles avec les caractéristiques détectées de la machine et les langues demandées sont proposés.

Le catalogue de paires Argos et Firefox peut être actualisé depuis la fenêtre. Les familles OPUS, NLLB, SMaLL-100, M2M-100 et Hy utilisent les versions fixées pour cette édition. NLLB est le modèle Meta diffusé sous licence CC BY-NC 4.0 ; les poids CTranslate2 sont téléchargés depuis le dépôt osa911/nllb-200-distilled-600M-ct2-int8 et le tokenizer depuis facebook/nllb-200-distilled-600M.

Langue source et réglages par application

Une langue source choisie manuellement a priorité. En mode automatique, une langue indiquée par le document est utilisée lorsqu’elle est disponible. Si vous avez explicitement activé la mémorisation de la langue de l’application, sa langue enregistrée peut ensuite être utilisée. Sinon, la détection est effectuée sur le texte. La langue de la voix NVDA n’est pas utilisée comme preuve de la langue du texte.

La mémorisation de la langue de l’application est désactivée par défaut : une annonce française du titre de fenêtre ne doit pas bloquer les traductions suivantes en anglais. Activez cette case seulement pour les applications dont la langue est stable. Vous pouvez oublier une langue enregistrée. Les réglages par application peuvent aussi hériter de la langue source globale.

Cache, mémoire et fermeture des applications

Les traductions déjà calculées sont mémorisées sur disque par application et par paire de langues, sans séparation par modèle. Le mode global dispose de son cache commun. Les anciens caches par modèle sont regroupés automatiquement en conservant les corrections et les fichiers d’origine. Elles peuvent être retrouvées après un redémarrage de NVDA. Ce cache contient donc les textes et leurs traductions.

Les modèles servent plusieurs applications : ils ne sont pas chargés une fois par application. Le moteur conserve les modèles nécessaires au trajet courant. Lorsqu’aucune application suivie n’est encore ouverte, le moteur est arrêté et libère ses ressources. Une fenêtre réduite reste ouverte et conserve le moteur. En mode global, le moteur reste disponible tant que la traduction globale est activée.

Changer ou supprimer les modèles

L’onglet des modèles installés affiche leur taille sur disque. Vous pouvez supprimer un modèle, choisir une autre famille et télécharger les paires voulues. Une suppression désactive la traduction ; le raccourci permet ensuite de la réactiver et de compléter les modèles manquants. Le cache et les réglages sont conservés. Les moteurs partagés, notamment Node.js ou CUDA, peuvent rester installés après la suppression des modèles.

Toutes les données sont placées dans le dossier de l’extension, sous LocalTranslateAccess/data : models contient les modèles, moteurs téléchargés, catalogue, mesures et choix de modèles ; cache contient les traductions et préférences de langue ; localTranslate.ini contient les autres réglages. Au premier démarrage, les anciens dossiers LocalTranslateAccess-models et LocalTranslateAccess-cache, ainsi que l’ancien fichier de réglages du profil NVDA, sont déplacés dans ce dossier. Une mise à jour conserve les données présentes dans l’addon. La désinstallation supprime ces données lorsque NVDA applique la suppression au redémarrage. Après une désinstallation complète, une nouvelle installation repart sans modèle. Aucun Python séparé n’est inclus : cette édition utilise le Python 64 bits de NVDA 2026.1.

Consulter, corriger et partager le cache

Le troisième onglet « Cache de traduction » permet de choisir une application (« Traduction globale » pour le mode global), de rechercher dans les textes et leurs traductions, puis de sélectionner une entrée. Avec Tab, lisez le texte d’origine complet en lecture seule, puis modifiez « Traduction à corriger ». « Enregistrer la correction » la sauvegarde immédiatement, sans utiliser Appliquer dans l’onglet Langues. Elle sera réutilisée pour le même texte exact, la même application et la même paire de langues, quel que soit le modèle installé, y compris après un redémarrage de NVDA. Les résultats automatiques ne remplacent pas les corrections manuelles. Les brouillons sont conservés lorsque vous changez de texte ou d’application dans la fenêtre, mais seuls les enregistrements sont conservés après sa fermeture. « Rétablir la traduction enregistrée » annule le brouillon et « Actualiser le cache » recharge les entrées. Une recherche affiche jusqu’à 1 000 résultats ; affinez-la si nécessaire.

« Exporter un cache » ouvre une liste d’applications à sélectionner avec les flèches et Espace. Le focus arrive sur « Toutes les applications », décochée par défaut ; aucune application n’est présélectionnée. Cette case sélectionne ou désélectionne toutes les applications. La case indépendante « Inclure le cache global » ajoute le mode global. Vous pouvez exporter le cache global seul, toutes les applications, plusieurs applications ou la totalité. Toutes leurs entrées enregistrées sont incluses, avec les traductions automatiques et les corrections, et pas seulement les résultats affichés par la recherche. Le fichier compressé .ltcache contient les textes et leurs traductions, sans modèles ni réglages de machine. Vous pouvez le partager vous-même.

« Importer un cache » permet de choisir un fichier .ltcache, puis les applications et le cache global à inclure. La case « Remplacer les traductions automatiques déjà présentes », cochée par défaut, permet de remplacer vos traductions automatiques par celles du fichier. Si elle est décochée, les entrées déjà présentes sont conservées. Dans tous les cas, les corrections manuelles déjà enregistrées chez vous sont protégées. Les corrections contenues dans le fichier sont également conservées comme corrections. Les langues, les réglages de traduction et les modèles installés ne sont pas changés. Un cache créé avec un modèle GPU peut donc être utilisé avec un petit modèle CPU. L’import indique le nombre d’ajouts, de remplacements et de corrections personnelles conservées. Les accès au disque se font en arrière-plan.

Mesurer les performances

L’onglet Performances affiche d’abord le temps du dernier chargement de chaque modèle, puis le temps moyen de traduction pour chaque paire de langues source et cible, avec le nombre de traductions mesurées. Les modèles et les paires de langues sont séparés : anglais vers français et allemand vers français ont chacun leur moyenne. Le mode de langue source est indiqué : Automatique ou Choisie manuellement. Ces deux modes ont des moyennes séparées. En mode Automatique, le temps moyen de détection est affiché avant le temps moyen de traduction pour la même paire de langues. Si la langue est fournie par le document ou mémorisée, aucune détection du texte n’est nécessaire ; son temps est nul pour cette traduction. Les résultats trouvés dans le cache et les traductions échouées sont exclus. Le chargement, la détection de la langue et la synthèse vocale ne sont pas inclus dans le temps de traduction. Un trajet par une langue intermédiaire compte comme une seule traduction, avec le temps total de ses étapes. La longueur des textes influe également sur la durée.

Ce nouveau calcul utilise les traductions mesurées à partir de cette version. Les anciennes mesures par étape restent dans le journal mais ne sont pas utilisées pour ces moyennes. Les mesures complètes de la version précédente ne connaissent pas le mode source ; elles restent séparées et portent la mention « mode non enregistré dans les anciennes mesures ». Les statistiques proviennent des traductions réalisées pendant l’utilisation de l’addon.

Le journal des performances ne contient pas les textes traduits. Il reste local et peut être effacé depuis cet onglet. Les téléchargements utilisent les sources publiques des projets concernés ; les textes à traduire ne sont pas envoyés à un service en ligne.
